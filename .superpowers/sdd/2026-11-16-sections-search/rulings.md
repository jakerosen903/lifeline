# Rulings — plan: docs/plans/2026-11-16-sections-search.md

R1. Store changes are read-only additions (allAliases, tellingWords), not "SearchReads.swift only" — repositories keep their database private — cost if wrong: two more public reads to maintain.
R2. An alias whose fold equals the title's is dropped from the index — insertPerson writes one for every person — cost if wrong: none seen; an old spelling still finds the person.
R3. A fact, feeling or goal sorts by when it was told; a half-dated moment shows no date line — a stored range no screen shows must not show through search (non-negotiable 3) — cost if wrong: order of facts in "Memories" differs from an entity page.
R4 (Task 5, 2026-11-19). Search is not a tab. An iPhone tab bar holds five tabs; with a sixth (role .search) iOS 26.3 folds You and Search into "More" (shots/t5-six-tabs-more.png). The five labeled sections are the owner's goal 1; "search is the trailing search tab" was the spec author's own call. Ruling: the five tabs stay as they are. Each tab's root gets a "Search" button (magnifying glass) in its top bar; it pushes SearchScreen in that tab's own stack. The record bar stays, results open pages in the same stack, Back returns to the results with the query kept. Decisions 15, 16 and 24 change to this; nothing else in the plan changes. — Why: it keeps the owner's five tabs and "search covers every section" from the mock-up, and keeps the record bar, which a sheet would cover. — Cost if wrong: one screen and its entry point move; the kit and the rows do not change. Each tab's search keeps its own query. The owner must look at the screenshots.
R5 (Task 5 review, 2026-11-19). The field takes focus when search opens, and while it is active iOS 26 shows a round "X" in place of Back. Ruling: "X" closes search and returns to the tab in one tap (the search's `isPresented` going false pops the screen). If the system also sets it false on Return or when a result's page is pushed, fall back to no auto-focus: the field is idle with Back showing, as the system does by default. — Why: one tap in, one tap out; the person must never be stuck on the results. — Cost if wrong: "X" loses the typed query, which is what closing search means.
