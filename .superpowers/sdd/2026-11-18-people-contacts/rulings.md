# Rulings — docs/plans/2026-11-18-people-contacts.md

- R1 (pre-flight): `candidate_person_choice.choice` holds `person`, `contact`, `new` or `not_a_person`.
- R2 (pre-flight): a memory's person links include the owner when the owner is linked. The plan said "never the owner"; today's memory page shows them.
- R3 (task 1): `Person` encodes all six new columns, so a `Person` round-trips through insert and update. Same pattern as `notes`: a stale `Person` value overwrites the contact fields on update. Callers that change only contact fields should use SQL, not a whole-record update.
- R4 (task 1): `LinkOrigin.stronger` treats nil as weaker than every case, including `new`.
- R5 (task 1): the v13 migration test now migrates `upTo: "v13"`, because v14 adds columns to `person` and `moment_entity` and the test compares whole rows. v14 has its own row-preservation test.
- R6 (after task 1 review): Task 3 also owns the four raw-SQL sites in `MemoryRepository` that copy a link with only `role_text`. Each must carry `origin` and `person_handle`, and on a key collision the surviving row keeps the stronger origin. Why: without it a memory merge or a kind change turns a marked guess into an unmarked link, which hides a guess (principle 5). Cost if wrong: Task 3 is larger.
- R7 (task 2): with a said name, only the name picks candidates; the relation part of a comma-form ref ("Priya, my mom") never picks a candidate, and rule 1 needs the person to hold the name as well as the relation. So a person who holds only the relation phrase is not a candidate; the relation decides rule 1 alone. With no name, the relation phrase picks the candidates (rule 2, or rule 4 when two hold it). Rule 2 never fires when a name was said, because "Priya, my mom" must not become the person who holds "my mom". A contact linked to a person makes that person a candidate when the contact fits. Rule 3 needs exactly one candidate whose full name (person `name`, contact `fullName`) equals the said name. Others: persons by rule-4 order, then contacts by full name.
- R8 (task 3): a stored choice applied on Keep is the owner's answer, so it saves both halves of the said name (the name and the relation phrase) as aliases of the chosen person, as settle does (Task 5, behaviour 1). A guess with origin `said` saves only the relation half. A group phrase is never saved. Why: the brief says only "the relation half"; the spec's move rule 5 saves both from an owner's answer. Cost if wrong: one extra alias per pre-Keep answer.
- R9 (task 3): a stored choice matches a ref by `SaidName.key` of the whole ref as said (`SaidName.raw`), not of its name part. "Robin" and "my roommate, Robin" are two keys. Task 5's `choose` and `preview` must key the chip's said name the same way.
- R10 (task 3): until PC-b, a guessed `.contact` (cannot occur: the contact list is empty) makes a new person with origin `new`; a stored `contact` choice makes a new person with origin `confirmed`. PC-b replaces both with a person linked to the contact.
- R11 (task 3): `ExtractionQueue.carried` counts a person mention as carried when a memory of the pass names it as a whole ref, as the name part of a comma ref, or by `about_ref`. After a serious disclosure no person mention counts as carried: the memories are withheld, no Keep will link the name, so it goes to the People queue instead of being lost.
- R12 (task 3): every write that can meet an existing link (Keep, Same story, memory merge, kind change, entity merge, an owner's link) keeps the stronger origin, with R4's order. So a link older than v14 (nil origin) takes `assumed` when a later telling guesses the same person, and shows the mark. The spec's "older links get no mark" holds for links no later telling touches. Why: a guess that reaches an old link is still a guess (principle 5).
- R13 (controller, on R12): R12 stands. An older link (no origin) that a later telling or a merge reaches with a guess takes that guess's origin and shows the mark. The spec's "Older links get no mark" and the constraint "Keep must not change an origin" are narrowed in Task 10's doc pass: an older link nothing touches has no mark, and Keep never settles a guess to `confirmed`. Why: the guess a retelling carries is real, and hiding it breaks principle 5; the archive-wide noise that decision 6 avoided does not arise. Cost if wrong: a narrow change in `raiseOrigin`. Flag for the owner in the final report.
- R14 (controller): a person made by a stored "Someone new" choice has `createdByGuess` false: the owner chose them, so a later move never removes them as an empty guess.
- R15 (controller): an alias saved before v14 that is a group phrase no longer links on Keep; the phrase asks again in each story, as the spec says for group phrases.
- R16 (task 4): a group holds links of the same relation as the chosen link (mention with mention, detail with detail), as well as the same person, session and `SaidName.key`. Why: the brief names only person, session and name; a detail link is not a said name, so it must not ride along with a mention. `links(to:)` returns both relations, which are `mention` and `detail` (the enum has no `about`).
- R17 (task 4): an `assumed` link with no said name still gets the word "Assumed" (and "{name}, assumed. Change who this is."), because ochre always comes with a word. `PersonChipLine` lives in its own file, `Domain/PersonChipLine.swift`, beside `PersonLink.swift`.
- R18 (controller, task 4 ⚠️): the link reads return every link whose memory row exists, hidden memories included; a withheld card has no memory row, so it has no link. Each view filters hidden memories as it does today. Why: a hidden moment about a person is still that person's, and matching must see it. Cost if wrong: a chip count that includes a hidden moment.
