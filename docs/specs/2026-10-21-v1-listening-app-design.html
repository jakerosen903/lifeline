1. Intent

V1 is one iPhone and one life. The owner opens the app and talks. A timeline fills in. The app listens, transcribes, extracts memories, places them as ranges, and ends every session with a landing. It does not speak back.

The reason to build this first is calibration. The recording study is deferred (see section 12). The owner's own sessions replace it. They give real speech, real pauses, and real extraction errors. So V1 must keep the raw audio and the transcript as the source of truth. V1 must be able to run extraction again over old sessions with a new prompt. This rule shapes the data model more than any screen does.

Who decided what

Owner iPhone app. Listen-only for V1. No separate server for V1. Anthropic Console API as the model provider. The recording study runs after V1 exists. Every interface must leave the door open to the full voice interviewer.

Builder The iOS internals in section 5. The data model in section 6. Extraction and resolution in sections 7 and 8. The milestones in section 11. These are proposals. The owner redlines them.

2. Goals, non-goals, anti-goals

Goals

  1. Record a 30 to 60 minute session with the screen off.
  2. Transcribe on the device with word timestamps. Keep the audio.
  3. After each completed thought, extract candidate memories, people, places and time anchors. Show them as one-tap cards.
  4. Resolve a name to a person once. The link holds across memories.
  5. Place memories as ranges, never points. Show inferred values as guesses.
  6. End every session with a summary in the owner's words and a keep / private / let go choice.
  7. Show the timeline: chapters, ranges, and the shelf for unplaced memories. Play a memory's own audio.
  8. Run extraction and resolution again over any past session, from the command line, without the phone.

Non-goals for V1

Designed for. Not built.

  • Spoken replies, acknowledgements, text-to-speech.
  • The end-of-thought classifier model. V1 uses a silence threshold.
  • Reflections and interviewer questions during the session.
  • Photos, music, family sharing, web viewer.
  • Chapter replay as a narrated story.
  • Detection of crying or other acoustic distress signals.
  • Memory kinds and domains: fact, feeling, goal, event; relationships, health, education, travel. See section 6.

Anti-goals

V1 fails if it does one of these, even if it works.

  • Shows an inferred date, name or place as a fact.
  • Fills in a detail the owner did not say.
  • Asks a form-style question for a baseline fact during a session. The optional "About you" screen at first open is the one place for typed facts.
  • Ends a session without the landing.
  • Keeps audio the owner chose to let go.
  • Sends audio off the device.

4. Architecture

The app target holds views, view models and the composition root. All logic lives in a Swift package, LifelineKit. The package compiles for iOS and for macOS. The command line tool and the tests use the same code as the app.

Rules

  • The App target must contain only views, view models and the composition root.
  • LifelineKit must compile for iOS and macOS. Speech and audio capture sit behind protocols with #if os(iOS) implementations.
  • The app must talk to the model only through ExtractionService.
  • No module may import the Anthropic client except Extraction.

5. iOS internals

Builder proposals The owner redlines each row. Open a row to see the reason and the alternative.

Minimum iOS: iOS 26

Why. SpeechAnalyzer and SpeechTranscriber (Speech framework, iOS 26) give on-device transcription with per-result audio time ranges and no one-minute cap. The owner's phone runs it.

Alternative. iOS 18 with SFSpeechRecognizer and on-device recognition. It works, but it has session limits and weaker timestamps.

Audio capture: one AVAudioEngine tap, two consumers

Why. The tap feeds the transcriber's input stream and an AVAudioFile writer (m4a, AAC, 24 kHz mono). One tap gives one clock. The file and the transcript share it.

Alternative. AVAudioRecorder plus a separate recognizer tap. That gives two clocks to reconcile.

Background: audio background mode

UIBackgroundModes: audio. AVAudioSession category .record, mode .spokenAudio. The app must pause the segment on an interruption or a route change and resume after it. Screen-off recording is the reason the app is native.

Silence detection: energy gate, not a model

An RMS energy threshold on the input tap, debounced. A segment ends after pauseThreshold (default 1.8 s) of silence that follows at least minSegmentSpeech (default 3 s) of speech.

Why. Cheap, on-device, tunable. The app logs the pause distribution. That log calibrates the later end-of-thought model.

Alternative. A Core ML voice activity detector can replace the gate behind the same protocol. Apple's own detector is not public API.

Word timestamps: SpeechTranscriber audioTimeRange

Store each attributed run as a word row with start and end milliseconds. Replay highlighting and let-go deletion need word-level spans.

Storage: SQLite via GRDB.swift

Why. The data model is relational with typed edges and derived spans. GRDB keeps the schema visible in code. Migrations live in code. ValueObservation drives SwiftUI. The CLI opens the same file.

Alternative. SwiftData. Faster to start. The schema is less explicit. It is awkward for the CLI and for raw SQL on ranges.

App architecture: SwiftUI + @Observable, one view model per screen

Dependencies are injected with a Dependencies struct from the composition root. A small app, testable, no framework.

Alternative. TCA. More structure than V1 needs.

Concurrency: Swift 6 strict, VoiceSession as an actor

VoiceSession emits an AsyncStream<VoiceEvent>. Extraction runs on one serialized background task queue per session. Candidates arrive in order.

Model client: URLSession to the Messages API

There is no official Swift SDK. Use Codable request and response types. Use structured outputs through output_config.format with the extractor JSON schema. Smallest dependency, schema-validated output.

Alternative. Community Swift SDKs. Not vetted.

API key: gitignored xcconfig → Info.plist → Keychain

Simple for one developer. Nothing in source. The app copies the key into the Keychain on first launch and reads it from there.

Audio location: Application Support, excluded from iCloud backup

Application Support/Lifeline/audio/<sessionID>.m4a. Hours of audio must not surprise a backup. The owner can enable backup.

Deletion: cut the span out of the file

Let go rewrites the session file with a time-range composition (AVAssetExportSession) and deletes the word rows. A tombstone records that a span was removed. The tombstone holds no content.

Rejected. Keep the whole file and mark the span hidden. That violates the anti-goal.

6. Data model

SQLite. All IDs are UUID strings. All times are ISO-8601 UTC. All audio offsets are integer milliseconds from the start of the session file. Select a table to see its columns.

Time range

A memory and a chapter carry these columns: earliest, latest, likely_start, likely_end (each YYYY-MM-DD or null), granularity (day, month, season, year, decade, era), origin (stated, inferred, derived, confirmed) and evidence_text (the owner's phrase that set it). A memory with all four dates null is unplaced. It goes to the shelf unless it is in a collection.

Later: kinds and domains

Owner's direction, 2026-10-21 A later version will sub-divide memories two ways. By kind: a fact, a feeling, a goal or intention, an event, or another kind. By domain: relationships, health, education, travel, work, and more. V1 does not add these columns. V1 keeps the seam open in three ways. First, candidate.payload is JSON. A later extractor version can emit kind and domain, and a re-run can back-fill every past session. Second, V1 code and copy must not assume a memory is an event. Third, collection_hint and chapter_hint stay free text, not an enum. The taxonomy itself is a later design.

Private memories

Builder's call A private memory is visible only under a Private filter on the timeline. The app must not put it in the context packet. The app must not put it in a summary sent to the model. The only export that holds it is the owner's full backup.

Invariants

  • A memory must have at least one span. Let go deletes every span of the memory, then the memory.
  • Candidate rows are immutable. A new extractor version writes new rows.
  • No row in memory, person or place may hold text the owner did not say or type. The one exception is title. The extractor proposes it. The owner accepts it with a tap.
  • A range with origin = inferred must render as a guess in every view.

7. Extraction

Extraction runs after each segment closes. The app sends the segment text and a context packet. Requests are serialized per session. If a request fails, the segment stays pending. The app retries it at session end. The CLI can retry it too. Step through one segment below.

Context packet

The builder on the device selects. It never dumps. The packet has: the previous two segments (about two minutes), people with aliases (cap 50), chapters with ranges, this session's memories so far (titles and ranges), open curiosity items (cap 10), and the session stage.

Output schema

{
  memories:  [{ ref, title, quote, segment_span: {start_word, end_word},
                people_refs: [string], place_text?: string,
                anchors: [{ phrase, relation, target_text?, value? }],
                same_as_memory_id?: string, collection_hint?: string,
                chapter_hint?: string, confidence }],
  mentions:  [{ text, kind: person|place, likely_alias_of_person_id?, confidence }],
  flags:     { serious_disclosure: bool, wants_to_stop: bool, wants_to_change_subject: bool }
}

Every field that carries content must be a span or a quote from the segment. The one composed field is title. The prompt limits it to the owner's own words, eight words at most.

Prompt rules

  • Extract only what is said. Never infer a year from a general fact. "I was in third grade" gives an age anchor, not a year.
  • A summary ("we went every summer") is a collection hint, not a memory, unless one instance is told. A named era ("the Boston years") is a chapter hint.
  • Mark confidence honestly. The UI hides nothing. It renders low confidence more faintly.
  • Return serious_disclosure for abuse, danger to self or others, or similar. The model classifies. The app's response is fixed text.

Model call

Model claude-opus-5-5. Adaptive thinking with low effort. Structured output with the schema above. Server-side fallback on refusal. One prompt-cache breakpoint after the fixed system prompt. Max tokens 4096. The model name and the effort are configuration, not code.

Idempotency

The pair (segment id, extractor version) is unique. A re-run of the same version does nothing. A new version appends rows. An accepted memory keeps its source candidate. A re-run can only add new pending cards.

8. Resolution

The resolver runs on the device after each extraction, and in the CLI. Input: anchors. Output: time ranges, floating memories, curiosity items. It must never ask for a date. It may generate one relative question per anchor, phrased as a choice between things the owner said. Try it below.

Algorithm, per memory, in this order

  1. Absolute. A stated date, season or year sets the range at that granularity. Origin: stated.
  2. Age. An age anchor and a known birth date give a one-year band, or the school-year band for grade phrases. Origin: inferred. The birth date comes from the "About you" screen at first open (origin typed, editable in Settings), or from speech (origin stated). If the two disagree, the app shows a "which is right?" card. It never picks silently. With no birth date, the memory floats.
  3. Relative to a placed memory or chapter. Before, after, during, or same year as a resolved target derives the band from the target's range. Origin: inferred.
  4. Relative to an unplaced target. Create a floating memory for the target. Link the anchor. Add a curiosity item with a payoff count: the number of memories that one answer would place.
  5. Collection membership. A memory in a collection with no range of its own renders inside the collection's span, still marked unplaced.
  • A confirmed range is never overwritten by the resolver.
  • A full re-run over all memories must give the same result as the incremental runs. The resolver is a pure function of anchors and confirmed ranges.

9. Session arc and safety

Stages: open, middle, wind-down, ended. The controller holds the elapsed time and the stage log. The numbers are configuration, not code. Move the slider to see what the app does at each minute.

Serious disclosure

The extractor returns the flag. The app stops new memory cards. The app shows one pre-written card from Arc/FixedResponses/disclosure.md: short, warm, one offer of help with a crisis line for the owner's locale, no insistence. The app moves to wind-down. A unit test asserts the text is shown verbatim. The model never writes it. The owner approves the wording and the line before M4.

Wind-down screen

A list of this session's memories, accepted and pending. Each quotes the owner. Each has keep, private, or let go. Default is keep. Keep on a pending card accepts it. Let go on a pending card dismisses it and deletes its span. Let go on an accepted memory deletes per section 5. One closing line comes from the top curiosity item, or a neutral line if the session was flagged heavy.

Builder's call Any card still pending after a session appears in a "Waiting for you" section at the top of the timeline. New cards from a later extractor version appear there too.

The session must not end without the wind-down screen, except on a crash. On the next launch the app resumes an un-landed session straight to its wind-down, with what was captured.

10. CLI and testing

Builder's call The app exports a session bundle (SQLite copy plus audio) through the share sheet. The CLI reads it. Nothing flows back. Re-running the extractor on real sessions is an in-app action in Settings that uses the same code. The CLI is for evaluation and prompt work.

CommandWhat it does
lifeline import <transcript.json>Loads an invented or consented transcript as a session.
lifeline extract --session <id> [--version v2]Runs the extractor. Prints candidates as a table.
lifeline resolve --allRuns the resolver again. Prints a diff against the current ranges.
lifeline eval <fixtures/>Runs extraction over fixture transcripts with hand-labeled expected candidates. Prints precision, invented-detail count and anchor coverage. This is the recording study's scoring, ready for when it runs.

Tests

  • Unit. TimeRange arithmetic. The resolver. Context packet selection and caps. Schema decoding. Fixed-response text verbatim. Let-go span deletion on a synthetic audio file.
  • Integration (macOS, needs a key, opt-in). The extractor over three invented fixtures. Assert that no field contains text absent from the transcript.
  • UI (iOS). The wind-down flow is reachable from every stage. Resume to wind-down after a simulated crash.

Fixtures are invented. No real person's data goes in the repo.

11. Milestones

Each milestone is usable on the owner's phone. M1 comes before M2 on purpose. The owner starts recording real sessions on day one. Every later milestone runs again over them.

M1
Record, transcribe, store, play back

A 30-minute screen-off session gives a session row, segments with words, and an audio file. A memory-less timeline shows the session. A tap on a segment plays it.

M2
Extract and confirm

Cards appear during a session. A tap creates memories and people. "Who's this?" works. The CLI runs extract on an exported session.

M3
Place

The resolver sets ranges. The timeline renders bands, collections, chapters and the shelf. The relative-question card narrows a range. Curiosity items show payoff.

M4
Land

Timer and button wind-down. Summary. Keep / private / let go with real deletion. Fixed disclosure response. Crash resume.

M5
Reprocess and tune

In-app re-run with a new extractor version adds new pending cards and does not touch accepted memories. The export bundle opens in the CLI. eval runs on fixtures.

12. Decisions made in this design

To add to docs/DECISIONS.md.

Recording study deferred until after V1 is usable

The owner's own sessions calibrate the extractor first. The eval command keeps the study's scoring ready.

V1 is listen-only

No TTS. No interviewer turns. VoiceSession ships as ListenOnlyVoiceSession. The commands say, acknowledge and interrupt are no-ops that log.

No separate server in V1

The app calls the Anthropic Messages API directly through ExtractionService. This supersedes the open "server language" item. When a server is needed, it is LifelineKit compiled as a Swift server executable.

Model provider: Anthropic Console API, billed by key

The Max subscription does not cover API calls. Default model claude-opus-5-5, configurable.

First user: the owner, telling their own life

"Hand the phone over" is not in V1.

Typed context at the start is allowed

An optional "About you" screen at first open takes name, birthday, birthplace and free text. Typed values carry origin typed. This is the one exception to "no form-style questions". In a session, the rule holds. Decided by the owner, 2026-10-21.

Memory kinds and domains are a later design

V1 ships one memory type and keeps the seam open. See section 6.

14. Open questions for the owner

1. Birth date. Resolved 2026-10-21. It comes from the "About you" screen at first open. See sections 3, 8 and 12.

2. Disclosure card. When the owner says something that signals serious harm (for example past abuse, or thoughts of self-harm), the app must show a fixed, pre-written card. It must not improvise a reply. The builder needs two things from the owner before M4: approval of the card's words, and the crisis line the card shows, which depends on the owner's country. Proposed draft, US: "Thank you for telling me that. You can stop here, or keep going. It is your choice. If you need to talk to someone now, call or text 988 (Suicide and Crisis Lifeline, US)."

15. Revisions after the design review (2026-10-22)

An external review of this spec, the M1 to M4 plans, the canvases and the Swift code found one theme: the combination of confirmation cards, people resolution, date refinement and session review could make the owner feel responsible for maintaining a database. The decisions below are recorded in docs/DECISIONS.md (entries dated 2026-10-22) and drawn as canvases R1 to R9. They change this spec as follows. The new principle is P9, preserve first, organize later.

SectionChange
§2 Goals 1, 6Two session lengths: a quick story (a few minutes) and settling in. Goal 6 becomes: end every session with a light landing; per-memory choices are optional and can happen later.
§3 First openTwo equally valid ways in; the optional About You screen stays but is secondary ("Add a little context"). The first payoff is the owner's own voice played back, minutes in.
§3 SessionTwo views. Listen (default): prompt, status, pause, finish, a small "N possible memories" count that never scrolls the screen. Transcript & memories: the review view, opened by choice. The session works with zero card taps.
§3 Landing"Your recording is saved. A few moments from today. Done for now · Review these moments." No required per-memory decision. Hide and delete one tap away. Neutral closing line after a heavy session. The copy "nothing is saved until you say so" is removed.
§5 DeletionDeletion must handle overlapping memories that reference the same audio and preserve playback offsets.
§6 Data modelAdd story and story_moment. memory is the moment. Chapters may overlap. visibility becomes two flags: hidden_from_timeline, excluded_from_ai.
§7 ExtractionReconcile related segments before presenting cards. Budget the context packet by tokens and relevance. Pending candidates count as context. same_as_memory_id becomes story_ref. Low confidence is a "Check this" label, never reduced opacity.
§9 ArchardStopAt becomes a wrap-up offer with an explicit "keep going", not a stop. During a heavy moment, suppress every organizational prompt including "who's this?". The disclosure flag distinguishes narration of the past from present danger.
§9 Wind-downReplaced by the light landing. Keep / private / let go moves to the review view and the privacy controls: Hide from timeline, Exclude from AI processing, Share…, Delete…. Local-only is chosen before recording.
§9 Stopstop must not wait for the extraction hook. Persist, show the landing, finish sorting in the background with durable retries.
CardsMemoryCard: Keep / Change… / Dismiss (with Undo; recording untouched). Keeping does not confirm inferred details. FlowChips must wrap. Visible alternatives to swipe and long-press.
§11 MilestonesM4 absorbs the landing and correction changes. M5 adds stories, the privacy controls and backup/restore. A minimal photo prompt (one photo, one story) follows as Phase 1.5.

The interactive arc above still shows the pre-review timer behaviour (a hard stop at 60 minutes). After the revision the 60-minute mark is a wrap-up offer, not a stop.
