# A1: One Title, One Story Implementation Plan

**Goal:** A story title names one story. Accepting a story hint joins the story that already has the title. Copies made before this fix become one story. A chapter with no title and no memory is removed.

**Spec:** `docs/specs/2026-11-16-audit-data-fixes.md`, "A1: stories" and "A1: chapters". `docs/DECISIONS.md`, "Owner's calls on the audit data fixes" (duplicates are merged once, without a question, with one notice).

**Scope:** kit code only. No migration. No screen. This PR was written in a cloud session that cannot compile Swift; CI's `swift test` is the only check it had.

## Rulings

1. **The match key ships here, used by stories only.** Extractor v7 (A2) adopts it for places, things, chapters and collections, and adds the stored column.
2. **A hint on a memory that is already in a story.** When another story has the title, only the hinted memory moves to it. The story it left keeps its other members, its title and its chapter. The first version of this PR moved the whole story; the review found that a hint about one memory must not move five, with no undo (PRINCIPLES 4 and 6).
3. **Ties on creation time.** `created_at` keeps milliseconds. The row order breaks a tie, so "the one made first" is always defined.
4. **The notice names the story when one title was repaired,** and counts the titles when there were several. Removed chapters are not in the notice: they held nothing.
5. **Empty untitled chapters are also removed when a memory changes chapter.** A memory that is deleted or merged away can still leave one behind; the launch repair removes it.

## Added on the branch `repair-at-launch`

The app now calls the repair. This was "not in this PR" above.

- `Dependencies.live()` and `Dependencies.uiTesting()` call `ArchiveRepair.run` one time, after the store opens. They keep `report.notice` in `launchNotice`.
- A repair that fails does not stop the launch. The app writes the error to the log and opens the data as it was. The next launch tries again.
- The shell shows the notice one time, above the record bar, on each tab. The notice has no Undo. It goes after 6 seconds or on a tap. VoiceOver says it.
- The notice waits while a session or a landing covers the shell.
- The slot is `NoticeSlot` in `ios/Lifeline/Screens/Shell/`. You uses the same view for "Hidden." and its errors.
- `RepairUITests` uses the seed `-uiTesting-seedDuplicates`: three stories with one title, and one empty chapter with no title.
- The owner must make a backup before the first install on the phone. This is the first build that changes stories that are already there.
