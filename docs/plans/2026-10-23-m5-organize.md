# M5 Organize — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The same moment told any number of times is one memory, one telling across a pause is one card, related moments are one story, and the extractor sees what matters within a budget.

**Architecture:** Three new kit tables (story, story_moment, duplicate_pair) and one span column; extractor v5 with `same_as_memory_ids`, `continues_candidate_id`, `story_ref`, `story_title_hint`; a second structured prompt, the reconciler, judging memory pairs in batches; a `DuplicatePass` that runs after the backfill and after a Keep; `StoryActions` and `MergeActions` extensions in `CandidateActions`; a budgeted `ContextPacketBuilder`. The app adds a pair card, a group line on the memory card, a story line with opt-out, story rows with menus on the timeline, and "Separate this telling" on the memory screen.

**Tech Stack:** Swift 6, SwiftUI, GRDB 7 (migration v8), Swift Testing, XCUITest, Anthropic Messages API structured output (existing client).

**Spec:** `docs/specs/2026-10-23-m5-organize.md` (read "Calls made after the builder check" too).

## Global Constraints

- Nothing merges, groups or is retitled without a tap. Keep includes only what the card shows. A declined pair never returns.
- Every telling keeps its audio and words; organization never deletes a span except through Delete.
- Story titles come from the person or from a kept hint built from the person's words (max 8 words).
- The packet budget is a ceiling of 6000 tokens, estimated as characters ÷ 4; relevance floors stay (`retrieveCount` 5; `retrieveMin` only for a calibrated model). Profile free text is never dropped. Same inputs, same bytes.
- Pair numbers in `PairConfig`: `pairTop 3`, `pairMin 0.55` (calibrated model only), `pairBatch 20`, at most 3 pair cards shown at once.
- Copy is fixed by the spec's Copy section (pair card, group line, story hints, story row, telling menu, "+ n segments").
- Kit tests: `cd ios/LifelineKit && swift test`. UI tests: `xcodebuild test -project ios/Lifeline.xcodeproj -scheme Lifeline -destination 'id=88EC5B09-3A30-4544-8145-F5246BB99AEE' -only-testing:LifelineUITests/<Class>`; run `xcodegen generate` in `ios/` after adding app or UI-test files.
- Fixtures are invented; never a real person's words.

## Review Focus

1. A pair whose memories were merged or deleted between the pass and the tap: the card disappears on refresh and Same story on a stale pair is refused, never applied to the wrong rows. Task 5 (`stalePairIsRefused`), Task 9 (refresh drops pairs whose memory is gone).
2. A continuation that arrives after the first card was dismissed: it becomes an ordinary card, never a silent extension of a dismissed one. Task 4 (`continuationAfterDismissIsItsOwnCard`).
3. Story membership on a card whose story was taken out or deleted before Keep: Keep creates nothing dangling; the memory lands with no story. Task 7 (`keepWithAVanishedStoryRefLandsAlone`).
4. The budget with a very long profile free text or a 200-memory archive: the packet never exceeds the ceiling by more than the profile text, every section still gets its first entry, and the bytes are stable. Task 3 (`budgetKeepsFirstEntriesAndProfile`).
5. Separate a telling that carries continuation spans and the only date: the continuation goes with it, the original re-derives, a stated range stays. Task 8 (`separatingTakesContinuationsAndRederives`).
